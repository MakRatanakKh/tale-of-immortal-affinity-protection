# Tale of Immortal — Partner Affinity Protection

**Status (September 19, 2026): experimental, NOT confirmed working in game.** An earlier build compiled and packed; the game recognized it in Local Mods, but our code's initialization messages did not appear. The user confirmed matching installed/built DLL hashes, newer runtime logs, and a complete game restart plus save load. Missing initialization remains unresolved.

Goal: prevent affinity decreases in either direction between the player and their current spouse/cultivation partners (道侣), while allowing gains and leaving unrelated NPCs unaffected.

## Current experiment: conventional six-character ID (v0.1.3)

Our initial custom ID `AffinityProtection` differed from the six-character IDs generated by TaleOfImmortalTool and used by published C# mods. It is **unknown whether that difference is the actual cause**. Version 0.1.3 changes the mod's identity consistently to `Rk7Qp2` / `MOD_Rk7Qp2` in project metadata, ModData, C# namespace, and DLL name. Affinity logic is otherwise unchanged. This is not a confirmed fix and this revision has not been built or loaded yet.

**Follow [`docs/six-character-id-test.md`](docs/six-character-id-test.md) for the precise test.** A full rebuild **and repack** are mandatory for the changed identity: just copying a DLL into the old package is insufficient. Remove only the obsolete local build DLL, check the package contains only `MOD_Rk7Qp2.dll`, disable and move the former experimental mod folder out of `ModExportData`, then import/copy the newly packed folder. Back up saves, because changing the mod ID can trigger missing-mod warnings. Never change unrelated mods or the game's MelonLoader installation.

Look for `AffinityProtection: Init ENTERED (six-character-ID diagnostic build 0.1.3)` in `%TEMP%/AffinityProtection-diagnostic.log` or MelonLoader logs. The game reporting it loaded a `ModExportData.cache`, or MelonLoader reporting `0 Mods loaded` from its **separate** generic mod loader, does not alone prove in-game C# entry-point execution or failure. Even if initialization and Harmony installation are logged, the affinity behavior still requires backed-up in-game verification.

## Implementation and limitations

[`ModCode/ModMain/ModMain.cs`](ModCode/ModMain/ModMain.cs) attempts to patch `DataUnit.RelationData.AddIntim(string,float,int,string,bool)` and `SetIntim(string,float)` and checks current `Married`/`Lover` relations. This is an in-game Tale of Immortal `ModMain.Init()` plugin, **not** a standalone `MelonLoader/Mods` plugin. The direct-write clamp compares float values against integer `GetIntim`, so sub-integer decreases might slip through. Other writers, `ClearIntim` and relationship breakups are not covered. No successful in-game protection has been established.
