# Six-character mod ID test (v0.1.3) — NOT confirmed to fix runtime loading

## Evidence and hypothesis

The user confirmed on Windows 11 that compiled and installed `MOD_AffinityProtection.dll` SHA256 hashes match, both Player.log and MelonLoader/Latest.log timestamps are newer than the DLL, and they fully restarted the game and entered their world. Player.log says the game's ModMgr loads `ModExportData.cache`, but there is no `Init ENTERED` from either diagnostic logger and no `%TEMP%/AffinityProtection-diagnostic.log`. This is evidence that the C# entry point has **not been shown to execute**; it is not proof of a specific loader defect. MelonLoader's `0 Mods loaded` applies to its generic Mods folder and does not itself diagnose in-game Local Mods.

The original custom ID `AffinityProtection` was much longer than the six-character IDs generated by TaleOfImmortalTool and used by published C# examples (`MOD_XXXXXX`). Whether six characters are mandatory is **unverified**. For an isolated compatibility test, this revision changes ONLY mod ID / namespace / assembly identity / diagnostic build marker, keeping the affinity logic and `isCreateNPC=false` otherwise unchanged:

- `ModProject.cache` `soleID`: `Rk7Qp2` (six characters)
- `ModData.cache` `modNamespace`: `MOD_Rk7Qp2`
- C# `namespace MOD_Rk7Qp2`, `ModMain` class unchanged
- `.csproj` assembly name: `MOD_Rk7Qp2` (resulting DLL `MOD_Rk7Qp2.dll`)

## Prepare (game MUST be closed)

Back up your save. Do **not** delete other mods or the game's MelonLoader installation. From the cloned repository root in PowerShell:

```powershell
git pull origin main
$gameDir = ([xml](Get-Content .\ModCode\Local.props -Raw)).Project.PropertyGroup.GameDir
# Remove ONLY the old DLL in the local BUILD folder; the packer copies all Release DLLs.
Remove-Item -LiteralPath .\ModCode\ModMain\bin\Release\MOD_AffinityProtection.dll -ErrorAction SilentlyContinue
dotnet build .\ModCode\ModMain\ModMain.csproj -c Release
```

**Stop if the build fails.** Check that the Release directory has exactly one `MOD_*.dll`, the new one:

```powershell
Get-ChildItem .\ModCode\ModMain\bin\Release\MOD_*.dll | Select-Object Name, Length
```

Then pack to the disposable Desktop destination (the `--clean` flag removes the existing generated Desktop output folder):

```powershell
toi mod pack . -o "$env:USERPROFILE\Desktop\AffinityProtection-test" --clean --glob '.git/'
$package = Join-Path $env:USERPROFILE 'Desktop\Mod_Rk7Qp2_AffinityProtection-test'
Test-Path (Join-Path $package 'ModExportData.cache')
Test-Path (Join-Path $package 'ModCode\dll\MOD_Rk7Qp2.dll')
Get-ChildItem (Join-Path $package 'ModCode\dll') -File | Select-Object Name
```

Expect both Test-Path results `True` and **only `MOD_Rk7Qp2.dll`** for MOD DLLs. Do not install if packaging fails or any old `MOD_AffinityProtection.dll` was copied into the package.

## Replace *only our* experimental mod safely

1. In game's Local Mods menu, **uncheck the old Partner Affinity Protection** (the original `Mod_AffinityProtection_AffinityProtection-test` folder), then completely exit the game.
2. Move ONLY `<GameDir>/ModExportData/Mod_AffinityProtection_AffinityProtection-test` out of `ModExportData` to a backup location outside that directory, e.g. your Desktop. Do not delete it or touch unrelated mods. If Windows reports a folder collision, choose a new backup location, not overwrite.
3. Copy the **entire** new `Mod_Rk7Qp2_AffinityProtection-test` folder from Desktop into `<GameDir>/ModExportData/`. The game's mod folder should contain `ModExportData.cache` and `ModCode/dll/MOD_Rk7Qp2.dll` directly inside it at the expected relative paths.
4. In game, check/enable the new `Partner Affinity Protection` entry, restart if requested, and enter a backup save. Replacing a mod ID can cause game saves to report a missing prior mod; do not overwrite original saves during this test.
5. Check `%TEMP%/AffinityProtection-diagnostic.log` and `MelonLoader/Latest.log` for `AffinityProtection: Init ENTERED (six-character-ID diagnostic build 0.1.3)` and subsequent patched/error lines.

```powershell
$diagnostic = Join-Path $env:TEMP 'AffinityProtection-diagnostic.log'
if (Test-Path $diagnostic) { Get-Content $diagnostic } else { 'Diagnostic file not created.' }
Select-String -Path (Join-Path $gameDir 'MelonLoader\Latest.log') -Pattern 'AffinityProtection' -ErrorAction SilentlyContinue
```

If missing, report only the new log result and confirm new entry was checked; the six-character hypothesis was not supported by this test. If it appears, inspect the next messages for patch installation errors; **still do not assume affinity is protected** without backed-up in-game behavior testing.
